# 需求規格說明書 (PRD #0076)：歷史現金股利入帳明細入帳日與除息日時序徹底分離、官方發放日校正與主次層級排版系統

## Problem Statement (問題陳述)

在「股利收益日誌與現金流全景」檢視中，「歷史現金股利入帳明細」存在時序概念混淆與資訊誤植的嚴重缺陷：
1. **概念混淆與欄位誤植**：明細表第一欄表頭標示為「入帳日期」，但底層元件直接渲染了除息基準日（`t.date` / `t.exDate`），導致所有標的（如 2886 兆豐金、2890 永豐金、0050 等）均顯示除息日而非實質入帳發放日。
2. **對帳衝突與體驗割裂**：投資人核對銀行交割帳戶存摺時，由於台股除息日與發放日通常相隔 3~4 週（約 28 天），日期完全無法匹配，造成使用者對系統準確度的質疑。
3. **流水排序失真**：歷史入帳列表依除息基準日倒序排序，造成除息日較早但發放日較晚之款項排序錯置，背離「資金到帳流水」以實際入帳日為時序主軸之直覺。
4. **官方日曆庫基準偏差**：官方除息基準庫中，永豐金 (2890) 現金股利預估發放日誤登記為 `2026-08-20`（與實際發放日 `2026-08-24` 偏差 4 天）。

---

## Solution (解決方案)

1. **時序徹底分離 (Temporal Separation)**：嚴格劃分除息日 ($Ex\text{-}Date$) 為假性虧損平滑與債權成立基準日，入帳日 ($Pay\text{-}Date$) 為資金實質落袋與可用現金交割日。
2. **主次並列呈現架構 (Primary-Secondary Dual Display)**：
   - 「入帳日期」欄位主視覺高亮顯示實際入帳日（`effectivePayDate`），若為未來款項則附加「預約待入」標籤。
   - 主日期下方以微縮灰階字體清晰標註「`📅 除息: YYYY-MM-DD`」，使核帳與除息追蹤一目了然。
3. **入帳時序精準倒序排序**：明細列表由原先依 `date` 排序，改為優先以 `effectivePayDate` 由新到舊倒序排序；若入帳日相同則依除息基準日倒序。
4. **永豐金 2890 發放日校正**：於官方日曆基準庫與公司行動掃描器中將 2890 現金股利之 `payDate` 統一校正為 `2026-08-24`。

## User Stories (使用者故事)

1. 身為使用現金股利對帳的投資人，我希望在「歷史現金股利入帳明細」的第一欄清楚看到「實際入帳日」，以便於我和銀行交割帳戶存摺明細精準核對。
2. 身為長期存股族，我希望能在同一個欄位同時看到該筆股利的「除息日期」，以便於我追蹤個股除息時點與除息至入帳所需的時間差。
3. 身為重視時序直覺的使用者，我希望歷史股利流水能嚴格按照「入帳日期」由新到舊倒序排列，以便於最新落袋的資金始終呈現在列表最上方。
4. 身為持有 2886 兆豐金的投資人，我希望 8 月 13 日除息的股利在入帳日期明確顯示為 9 月 4 日，以便於消除除息日與入帳日混淆的困擾。
5. 身為持有 2890 永豐金的投資人，我希望 7 月 23 日除息的股利在入帳日期明確顯示為 8 月 24 日，以便於獲得與官方公告 100% 一致的發放資訊。
6. 身為持有即將入帳股利的投資人，若入帳日晚於當前日期，我希望在入帳日旁看見醒目的「預約待入」標籤，以便於區分已實質落袋與待交割資金。
7. 身為搜尋歷史股利的使用者，我希望在關鍵字搜尋代碼或名稱時，篩選出的結果依然維持嚴格依入帳日倒序排列。
8. 身為檢視不同市場（台股/美股）的投資人，若交易紀錄中無明確 `payDate`，我希望系統能自動依市場慣例（台股 28 天、美股 21 天）合理推算預估發放日並優雅降級呈現。

## Implementation Decisions (實作決策)

1. **有效入帳日解析規則 (Effective Pay-Date Resolution)**：
   - 採用共用推算縫隙：`effectivePayDate = t.payDate || estimatePaymentDate(t.exDate || t.date, t.market)`。
   - 優先讀取紀錄上顯式指定之 `payDate`；若無則透過 `estimatePaymentDate` 自動自官方基準日曆庫或天數推算。
2. **列表複合排序鍵 (Composite Sort Keys)**：
   - 主排序鍵：`payB.localeCompare(payA)`（入帳日降冪）。
   - 次排序鍵：若入帳日相同，依 `(b.exDate || b.date).localeCompare(a.exDate || a.date)`（除息日降冪）。
   - 保證時序確定性 (Deterministic Sorting)。
3. **主次層疊排版結構 (Dual-Layer Typography)**：
   - 容器：採 Vertical Flex 佈局（`gap: 2px`）。
   - 第一層（主）：`fontSize: 0.85rem`、`fontWeight: 700`、色票 `#34d399`（到期）或 `#fbbf24`（預約待入）。
   - 第二層（副）：`fontSize: 0.7rem`、色票 `#94a3b8`，標籤格式為 `除息: YYYY-MM-DD`。
4. **官方日曆基準庫常數校正**：
   - `OFFICIAL_DIVIDEND_CALENDAR` 與 `knownPayDates` 中，永豐金 2890 現金股利之 `payDate` 由 `2026-08-20` 校正為 `2026-08-24`。
   - `corporateActionScanner.ts` 中 2890 現金股利事件同步校正。

## Testing Decisions (測試決策)

1. **公開介面縫隙測試 (Test at the Seam)**：
   - 不針對 React 內部 DOM 渲染狀態進行脆性綁定，而是針對公開導出的計算函數與資料流縫隙進行驗證：
     - 縫隙 A：`estimatePaymentDate` 官方日曆輸出（驗證 2886 為 `2026-09-04`，2890 為 `2026-08-24`）。
     - 縫隙 B：明細排序比較器邏輯（驗證有效入帳日倒序排列行為，除息日早但入帳日晚者正確排前）。
     - 縫隙 C：`scanCorporateActions` 回傳事件之 `payDate` 精準度。
2. **先紅後綠 (Red-Green-Refactor)**：
   - 先建構預期 2890 為 `2026-08-24` 之紅燈測試，確認斷言失敗後修復實作，再達成全量 491 項測試 100% 綠燈。
3. **既有測試防禦**：
   - 確保二代健保合併計算（配股 + 配息）、現金帳交割排程（`cashLedgerEngine`）不受影響。

---

## Out of Scope (範圍界定)

1. **表格欄位結構增刪**：維持目前明細表 8 欄標準格局，不額外新增獨立除息日欄位，避免擠壓行動端或小螢幕寬度。
2. **歷史已結算現金帳逆向修改**：本規格僅聚焦於前端日誌展示與排序呈現，不回溯修改舊有已存於資料庫中已對帳之非股利交易。
3. **即時第三方行情 API 輪詢除息日**：維持透過官方 Session 快取與既有 scanner 機制，不引入額外高頻外部 API 呼叫。
