# 需求規格說明書 (PRD #0053)：本機公司行動資料庫 (IndexedDB)、多源交叉增量同步管線、減資時序回溯與除息入帳日校準系統

## Problem Statement

使用者在管理台股與美股長線投資組合時，面臨歷史公司行動（減資、分割、配權配息）與金流時序計算上的三大痛點：

1. **減資歷史事件遺失導致除息金額與股數嚴重高估**：
   - 泰銘 (9927) 於 2025-09-15 實施過 28.28% 現金減資，但在比對 2026-10-01 的 5.0 元現金股利時，因第三方資料源（如 Yahoo Finance）未成功回傳減資換發，系統誤以減資前舊股數（12,829 股）計算，得出 $12,829 \times 5.0 = 64,145$ 元之錯誤金額，而非減資與後續交易補正後實質在籍 10,000 股之正確金額（毛額 50,000 元，稅後 48,945 元）。
2. **除息日與入帳發放日錯置**：
   - 系統先前將泰銘 (9927) 2026-10-01 除息事件之預估發放日錯置為當日（`payDate: '2026-10-01'`），導致除息日被誤當作資金入帳交割日，破壞了現金帳本的在途款項隔離機制（正常發放日應為 2026-10-29）。
3. **缺乏本機持久化公司行動資料庫與可靠多源同步**：
   - 目前公司行動完全依賴暫時性記憶體與 24H 快取，未在本機 IndexedDB 建立永久儲存庫；每次全量重新查詢容易受到外部 API Rate Limit 阻擋或 CORS 失敗，且缺乏「增量更新 (Incremental Sync)」與「以時間換空間慢速回填」機制。

---

## Solution

建立完整的「本機公司行動資料庫 (IndexedDB)、多源交叉增量同步管線與減資除息時序校準體系」：

1. **本機持久化公司行動資料庫 (`StockTrackerDB.corporate_actions`)**：
   - 在 IndexedDB 建立專屬物件儲存庫，以 `symbol-type-date` 為主鍵，支援本機離線極速存取。
   - **增量更新機制**：記錄 `lastSyncTimestamp`，日後同步只針對新增或異動之事件進行差異化寫入，消除重覆拉取負擔。
2. **三層多源交叉驗證管線 (Three-Tier Pipeline)**：
   - **第一層 (內建官方重大基準庫 SSOT)**：內建 9927 減資、2330、2886、00878、00923 等重大除權息與減資事件，保證 100% 離線可用。
   - **第二層 (臺灣官方 OpenAPI - 免 Key)**：串接 TWSE `TWT48U_ALL`（除權息預告）、`TWTAVU`/`TWTB4U`（減資恢復買賣）與 TPEx 官方開放端點，支援民國年自動轉西元年。
   - **第三層 (歷史深度回填 - 選填免費 API Key)**：
     - **台股**：在設定頁支援填入 **FinMind Token**（免費申請，每日 600 次額度），支援「以時間換空間」慢速節流（200ms 間隔）背景回填歷史 10 年減資與除權息。
     - **美股**：支援選填 **FMP** / **Finnhub** 免費 Key 或 Yahoo Finance 備援。
3. **泰銘 (9927) 交易時序與金流全面校準**：
   - 納入 2025-09-15 現金減資（28.28%，每股退款 2.828 元）。
   - 經減資與後續交易時序回溯，2026-09-30 在籍持股精準鎖定為 **10,000 股**。
   - 2026-10-01 除息事件：`exDate: '2026-10-01'`, `payDate: '2026-10-29'`, 未稅毛額 **50,000 元**，扣除 2.11% 二代健保（1,055 元）後實質入帳 **48,945 元**。
   - 現金帳本連動流水同步校正為 `+NT$ 48,945`，於 2026-10-29 到達前保持 `PENDING` 待交割狀態。

## User Stories

1. 作為一名長線投資人，我希望系統在本機建立永久的公司行動資料庫，日後更新時僅抓取最新增量事件，不再每次耗時全量重掃。
2. 作為一名重視資料精確度的投資人，我希望在設定頁填入免費的 FinMind Token 後，系統能以符合 API 規範的節流速度自動回填台股過去 10 年的歷史減資與配股配息，補足 Yahoo API 遺漏的減資事件。
3. 作為一名泰銘 (9927) 持股者，我希望系統計算 2026-10-01 除息時，能精準反映減資後與後續交易之 10,000 股在席股數，產生正確的 50,000 元股息（稅後 48,945 元），並清楚標明 2026-10-29 為預估入帳日。
4. 作為一名注重現金流風控的記帳者，我希望當除息金額或發放日被校準後，現金流水帳本中的自動連動流水能以冪等方式同步更新，在發放日前維持待交割在途狀態，不提前虛增可用現金。

## Implementation Decisions

### 1. 本地資料庫儲存模型 (IndexedDB Schema Upgrade)
- 升級 `StockTrackerDB` 版本，新增 Store `corporate_actions`：
  - Key: `id` (格式: `${symbol}-${type}-${date}`)
  - 索引: `by_symbol` (`symbol`), `by_date` (`date`), `by_type` (`type`)
  - 欄位包含 `symbol`, `name`, `market`, `currency`, `type`, `date`, `exDate`, `payDate`, `ratio`, `price`, `cashAmount`, `sourceType`, `verifiedSources` 等。

### 2. 設定頁 API Key 欄位與同步面板 (Settings Panel Integration)
- 在 `SettingsWorkspace.tsx` 的「API 與資料同步」面板中新增：
  - **FinMind API Token** 輸入欄位（附免費申請連結說明）。
  - **FMP / Finnhub API Key** 輸入欄位。
  - 「公司行動增量同步」與「歷史資料深度回填」按鈕（帶即時進度條與背景受控節流 200ms 防護）。

### 3. 多源交叉驗證與同步引擎 (Sync & Cross-Verification Engine)
- 在 `corporateActionScanner.ts` 中建立 `syncCorporateActionsToDB`：
  - 優先讀取本地 IndexedDB。
  - 調用 TWSE/TPEx 官方端點抓取最新除權息與減資快照。
  - 若配置了 FinMind Token，發起歷史資料增量查詢，將新事件寫入本地 IndexedDB。

### 4. 泰銘 (9927) 專項校正 (9927 Calibration)
- 官方行動庫補全 `9927` 於 `2025-09-15` 之現金減資（`ratio: 0.2828, price: 2.828`）。
- 修正 `9927` 於 `2026-10-01` 之除息事件發放日為 `2026-10-29`。
- 確保時序計算在席股數為 `10,000` 股，計算毛額 `50,000` 元，稅後淨額 `48,945` 元。

## Testing Decisions

### 1. 測試原則
- 遵循行為驅動 (BDD) 與測試驅動開發 (TDD) 原則。
- 在公開介面縫隙編寫測試，嚴格驗證本地 IndexedDB 存取、時序減資回溯與發放日判定。

### 2. 測試範疇
- **IndexedDB `corporate_actions` Store 單元測試**：
  - 驗證 CRUD、批次寫入、增量更新與去重機制。
- **泰銘 (9927) 時序回溯與除息計算測試**：
  - 驗證經歷 2025-09-15 減資後，在籍股數為 10,000 股時，2026-10-01 除息之計算毛額為 50,000 元，稅後淨額為 48,945 元，預估發放日為 2026-10-29。
- **現金流水帳連動與交割測試**：
  - 驗證當 `today < 2026-10-29` 時，現金帳本中呈現 `PENDING` 在途，金額為 48,945 元；當 `today >= 2026-10-29` 時自動轉為 `SETTLED`。
- **全量測試與打包驗證**：
  - 執行全量 `npm test`（100% 通過）與 `npm run build`（TypeScript 0 錯誤）。
