# Spec 0232: 近日持倉除息行事曆雷達與跨期現金流前瞻排程規格

## Problem Statement

長期投資人與存股族在檢視「股利日誌與被動現金流」頁面時，面臨以下關於「除息掌握度」與「現金流前瞻調度」的困境：

1. **缺乏即時持倉除息動態視窗**：目前頁面雖具備過去除息紀錄與未來 12 個月的月度粗粒度柱狀預估，但對於「當前已持倉股票最近幾週或一兩個月內即將除息」的確切日程，缺乏一個直觀、按時間排序且能倒數提醒的專屬行事曆/雷達。
2. **除息日與入帳日混淆引發流動性誤判**：除息日（Ex-Date，扣折股價與確立除息權益日）與入帳發放日（Pay-Date，現金實際匯入銀行戶頭）之間通常存在 20 至 35 天的交割入帳時間差。若介面未清晰標明雙重時序，投資人易將除息日當作資金可動用日，影響資金再平衡或日常開銷調度。
3. **二代健保與稅負摩擦事前無感知**：單筆現金股利達 20,000 元新台幣即需扣除 2.11% 二代健保補充保費，美股亦有 30% 預扣稅。投資人常於收到發放通知書或實際入帳時才驚覺被扣款，在除息日前缺乏事前警示與股數調度試算依據。
4. **公告確定日與歷史週期估算脫鉤**：許多上市公司在除息日前 30 天內才陸續召開董事會定案除息日。若行事曆僅呈現官方公告，未來視野常出現斷點空白；若僅憑猜測，又易產生日期偏差。需要一套兼顧「已正式公告確定」與「歷史週期統計推估」的動態分層視野。
5. **多券商與多市場篩選脫鉤**：在台美混持或多券商戶頭環境下，若使用者切換特定券商帳戶或特定市場（台股/美股）時，即將除息清單未同步連動過濾，會造成資訊雜訊。

---

## Solution

在「股利日誌與被動現金流」工作台中，新增「**近日持倉除息雷達與行事曆 (Ex-Dividend Radar & Calendar Horizon)**」卡片模組：

1. **專屬持倉除息時序雷達**：針對使用者當前有效持倉（股數大於 0），結合官方已排定除息日與歷史發放週期，依除息日期升冪排列，清晰呈現近 60 天（確定公告期）至 90 天（週期推估期）的即將除息事件。
2. **雙時序雙軌呈現 (Ex-Date vs. Pay-Date)**：每個事件標示除息倒數天數（如 `T-5 天除息`）、除息基準日、預計發放日以及兩者之間的資金在途凍結天數，徹底消弭流動性預期落差。
3. **稅前/稅後金額與二代健保穿透警報**：依據持倉股數與預估每股配息，精確計算預估總配息（Gross）與預估實質淨配息（Net）。若單筆金額達 20,000 元門檻，自動標註「二代健保扣繳警示徽章」，並顯示預估扣繳保費與免扣繳建議臨界股數。
4. **狀態分層標籤**：明確區分「官方確定公告（Confirmed）」與「週期統計預估（Projected）」，維持數據透明度與可信度。
5. **全局券商與市場聯動**：完全遵循全域 `selectedAccountId` 與 `market`（ALL/TW/US）篩選狀態，精確對齊單一券商與全市場檢視。

## User Stories

1. 作為長期存股投資人，我希望在股利日誌頁面上方看見一個按時間排序的「近日持倉除息行事曆」，以便隨時掌握未來 60 天內手中有哪些股票即將除息。
2. 作為現金流管理者，我希望在每筆除息事件上能同時看見「除息日」與「預計入帳發放日」，以便精確掌握資金何時會真正到帳，避免提早動用資金造成透支。
3. 作為台股高股息 ETF 與權值股持有人，我希望系統在單筆配息總額 $\ge 20,000$ 新台幣時自動高亮顯示二代健保 2.11% 警示，以便我在除息日前評估是否調度持股或提早做好稅負預算。
4. 作為注重資本效率的投資人，我希望知道除息日距離今天還有幾天（倒數計時 T-X），以便安排除息日前後的加碼或再投資策略。
5. 作為擁有多個券商子帳戶的使用者，當我切換特定券商時，行事曆雷達應僅顯示該券商持有標的的除息資訊，以便針對單一帳戶進行資金盤點。
6. 作為台美股雙棲投資人，當我切換市場為「美股」或「台股」時，行事曆應即時篩選出該市場的除息項目，並在美股項目上自動反映 30% 預扣稅後的實質到帳金額。
7. 作為資產總覽檢視者，我希望在行事曆卡片頂部看見彙整指標：包括「近 60 天預計除息檔數」、「預估稅後除息總金額」與「可能觸發健保費總額」，以便一眼掌握近期現金流規模。
8. 作為重視資料真實性的使用者，我希望行事曆能以標籤標註該筆除息是「官方已公告」還是「歷史週期預估」，避免將尚未確定之董事會決議誤認為既定事實。
9. 作為在除息日前出清持股的使用者，一旦我將某檔股票全部平倉賣出，該股票應即刻自「近日即將除息行事曆」中移除，不干擾視線。
10. 作為在除息前夕買進加碼的使用者，若我於除息日前新增買進交易，行事曆雷達中該標的之除息總額應隨之動態更新為最新持股規模。
11. 作為跨午夜長期開著應用程式的使用者，當系統時間跨過午夜 00:00 時，倒數天數（T-X）與狀態機應自動重新計算，不需手動重新整理頁面。
12. 作為極簡閱讀偏好的使用者，我希望可以折疊或展開即將除息行事曆卡片，保留螢幕空間檢視下方的年度月度趨勢圖表。
13. 作為追求極致對帳體驗的使用者，當某筆除息事件正式到達「除息日」後，該項目能平滑轉換為「待入帳」狀態，引導我至下方待入帳明細進行一鍵入帳。
14. 作為持有零股的投資人，行事曆上的預估金額應按實際零股股數精確運算（如 150 股配 1.5 元），不可因無條件進位造成計算失真。
15. 作為使用手機或平板閱讀的使用者，行事曆雷達在小螢幕上應維持良好的響應式流動佈局，資訊不重疊破版。

## Implementation Decisions

1. **模組定位與生命週期整合**：
   - 於被動現金流工作區建立獨立的除息時序雷達元件，掛載於現金流摘要下方、月度長條圖與歷史對帳表上方，作為近期前瞻決策第一道防線。
   - 與既有應收股息引擎整合：直接複用當前持倉計算函式與應收股息計算核心，以當前台北基準日 `todayStr` 作為比較軸，擷取有效持倉中除息日大於或等於今日之事件。

2. **時間跨度雙軌規格 (Confirmed 60d vs. Projected 90d)**：
   - 時間範圍預設為未來 60 天內（官方公告覆蓋最完整區間）。
   - 提供擴展開關，允許使用者探索至未來 90 天（含季配/月配型 ETF 依歷史發放日推估之事件）。
   - 官方確認事件標記為 `CONFIRMED`，週期估算事件標記為 `PROJECTED`。

3. **實質收益與稅務警戒推導模型**：
   - 台股除息事件依券商與持股計算 `grossTWD = shares * cashDividendPerShare`。
   - 健保警報判別：`grossTWD >= 20000` 觸發 `isNhiTriggered: true`，計算 `estimatedNhiFee = Math.round(grossTWD * 0.0211)`。
   - 美股除息事件依即時/設定匯率換算 TWD，並直接套用 30% 外國人扣繳稅率扣除，呈現真實可用金額。

4. **複合資料結構 (Data Shape Prototype)**：
   ```typescript
   export interface UpcomingExDividendRadarItem {
     id: string;
     symbol: string;
     name: string;
     market: 'TW' | 'US';
     currency: 'TWD' | 'USD';
     accountId?: string;
     exDate: string;                  // YYYY-MM-DD
     payDate: string;                 // YYYY-MM-DD
     daysUntilEx: number;             // 倒數天數 (0 代表今日除息)
     daysFromExToPay: number;         // 除息至發放之工作/日曆天
     scheduleType: 'CONFIRMED' | 'PROJECTED';
     sharesHeld: number;
     cashPerShare: number;
     estimatedGrossTWD: number;
     estimatedNetTWD: number;
     isNhiTriggered: boolean;
     nhiFeeTWD: number;
   }
   ```

5. **篩選與排序一致性契約**：
   - 排序原則：依 `exDate` 升冪排序（最近要除息者排在最上方）；同一天除息者，依 `estimatedNetTWD` 降冪排序。
   - 範圍邊界：$\mathcal{D}_{\text{ex}} \ge \mathcal{D}_{\text{today}}$ 且 $\mathcal{D}_{\text{ex}} \le \mathcal{D}_{\text{today}} + 60\text{d}$（或 90d）。
   - 帳戶隔離：若指定 `selectedAccountId`，僅匹配持倉與交易屬於該帳戶之標的；若為 `ALL` 則跨帳戶彙整。

## Testing Decisions

1. **良性測試準則 (Behavior-Driven Testing)**：
   - 只測試對外暴露之計算結果、時序過濾正確性與渲染文字，嚴禁刺探或綁定內部私有變數。
   - 測試必須在真實 DOM 或純粹引擎輸出階層運行，杜絕使用偽裝模擬函式複製業務邏輯。

2. **核心測試模組與覆蓋範圍**：
   - **時序邊界與倒數驗證**：測試今天、明天、59 天後與 61 天後的除息事件，確保落在 60 天區間外的事件被精確排除。
   - **二代健保臨界測試**：測試單筆 19,999 元（不觸發）與 20,000 元（精確觸發 2.11%）之邊界數值。
   - **除息與入帳雙日曆解耦**：驗證 `exDate` 到 `payDate` 的凍結期天數計算無跨時區偏差。
   - **帳戶與市場過濾測試**：驗證在台美切換與特定券商過濾下，非相關標的 100% 隱藏。

3. **參考前例 (Prior Art)**：
   - 參照既有 `src/components/DividendLogView.test.ts` 與 `src/engine/receivableDividendEngine.test.ts` 中的時區凍結 (`vi.setSystemTime`) 與純淨數據斷言。

## Out of Scope

1. **非持倉股票的市場除息行事曆**：本模組專注於使用者「當前手中已持有部位」的除息雷達，不負責全市場上千檔未持有股票的行情預告。
2. **自動代客下單或除息前自動賣出**：系統僅提供稅負預警與倒數資訊，不涉及任何券商下單 API 執行。
3. **借券出借收益即時競價**：不包含借券市場即時費率搓合，僅在 UI 上提示稅務評估。

## Further Notes

- 本模組的加入可與既有的「12 個月現金流預測」及「待入帳對帳」形成前後呼應的三幕式現金流工作台：
  1. **第一幕：近日持倉除息雷達 (Pre-Ex)** $\to$ 聚焦未來 60 天，掌握除息日與稅負。
  2. **第二幕：12 個月現金流展望 (Projections)** $\to$ 聚焦全年平滑化開銷覆蓋與退休金缺口。
  3. **第三幕：歷史對帳與入帳明細 (Post-Pay)** $\to$ 聚焦資金確實落袋與真實 YOC 計算。
