# Spec 0246: 外部資料更新中樞收斂（單一缺口調諧）、NAS 分軌水位線自治排程、靜態快取退役與 Card 01 盤中實量縫合

## Problem Statement

使用者於 QNAP NAS Docker 容器環境（24/7 長駐）與本機開發環境進行驗證時，系統外部市場資料出現多處停滯與前後端分裂現象——即使於 11 月 24 日交易時段開啟系統，本機主力戰情室 `Card 01 主 K 線圖` 成交量與台股日線湖倉仍停留在 11 月 19 日，且本機 SQLite 湖倉在近 30 個日曆日內累積達 8 個週五／週一斷層缺口，NAS 端資料更是長期未自動前進。

經全量底層溯源，根因並非單一爬蟲失效，而是系統歷經多次迭代後累積了八項結構性缺陷：

1. **NAS 自治排程跨市場共用單一日鎖導致台股週二至週五系統性餓死**：排程器將台股與美股綁定於單一每日執行旗標。每逢週二至週五台北清晨 06:00 美股盤後到期觸發每日例行任務時，同批次誤帶入開盤前之台股同步（空回傳），卻無條件將全域每日旗標標記為「今日已完成」，直接鎖死當日下午 15:30 以後的台股盤後收盤同步與重試機會。
2. **補齊與日更皆屬「缺口盲視（Gap-Blind）」**：啟動追趕任務僅呼叫無日期參數之單日同步，盤中執行時因當日尚未收盤即空跑結束，完全不檢查並補齊先前遺漏之已結算交易日；且不完整日期偵測僅掃描資料表中已存在之日期列，無法察覺完全缺漏之交易日。
3. **三處跨模組參數與匯出契約斷裂**：NAS 排程傳遞設定物件予預期接收日期字串之台股日更函式，不僅誤繞過休市日防護，亦導致自訂資料庫路徑於下層子攝取全數靜默失效；本機中介層傳遞錯誤參數鍵名予美股同步函式導致自訂路徑被忽略；每週湖倉維護任務匯入不存在之 ETF 元數據函式名、誤將 ETF 淨值回傳物件當成數值運算並遺漏交易日定錨，造成週排程 100% 失敗。
4. **Docker 執行期映像遺漏法定休市日曆**：容器正式階段僅封裝編譯產物與腳本，未攜帶台美休市日曆資料檔，導致 NAS 容器內台美休市集合全空，逢國定假日即誤判資料過期並觸發無效重試或錯誤缺口警示。
5. **靜態 JSON 市場快取腦裂、一年期不可變快取頭與 IndexedDB 單根覆寫**：NAS 靜態伺服器對 JSON 資產回傳一年期 `immutable` 快取標頭，Docker 映像內封存之靜態市場快取凍結於建置日；同時前端每次啟動皆下載逾 5 MB 過期靜態快取，並以單日過期報價循序覆寫本地 IndexedDB 既有的 250 日歷史 K 線快取；此外，台股日更路徑缺少與歷史回補一致之上櫃權證過濾規則。
6. **Card 01 盤中即時縫合遺漏真實 OHLCV 導致成交量停滯於舊結算日**：即時報價解析器僅提取現價與漲跌幅，未提取盤中開、高、低、成交量，使主 K 線盤中縫合 K 棒固定注入零成交量（十字線），進而讓量能與成交量顯示被迫定錨於過期結算日。
7. **四套分歧結算時鐘、空表陳舊盲點與美股跨時區 Checkpoint 偏移**：前後端結算判定各自獨立且前端忽略法定休市日；鮮度評估在全新空資料庫（週集保或月營收尚無任何列）時誤回傳「未過期」導致新部署 NAS 永不自動建庫；美股 Checkpoint 誤以台北當地日期鍵入而非美東已結算交易日。
8. **五組各自為政的觸發入口與前端追趕完成無輪詢**：NAS 排程、本機中介層、CLI 日更與全市場回補各自持有獨立鎖且互不感知，前端觸發追趕後亦未於背景追趕期間輪詢完成狀態，導致畫面無法自動刷新至最新結算日。

## Solution

秉持「單一事實來源（SSOT）、最小爆破半徑、零新增外部依賴（KISS）」原則，將散落於多模組的外部資料更新機制收斂為單一可證偽的 **缺口集合調諧引擎（Gap-Set Lakehouse Reconciliation）**，並同步完成四條垂直架構收斂：

1. **單一結算時鐘、休市日曆容器化與跨模組契約統一**：
   - 收斂台美結算截止門檻與法定休市日曆為單一共享定義，確保 Docker 正式執行映像完整攜帶休市日曆，並消除前後端對「最新應結算交易日」的口徑落差（補齊 2026 實戰休市日：10/23 薔琵颱風停市、10/26 光復節補假、12/25 行憲紀念日）。
   - 修復空表陳舊盲點（無資料表列必判為陳舊待補）與歷史補抓日 TWSE-only 覆蓋底線（避免因 TPEx OpenAPI 僅支援當日快照導致歷史補抓日陷入無限陳舊重試）；統一台美同步設定物件介面、修正每週維護匯出契約與交易日定錨，並將美股 Checkpoint 鍵值改以美東已結算交易日定錨。
   - 台股日更與歷史回補統一共用相同之上櫃權證濾除規則，消除雙軌資料差異。
2. **單一湖倉同步調諧中樞與 NAS 分軌獨立水位線自治排程**：
   - 建立單一共享同步調諧中樞（`lakehouse-sync-coordinator.cjs`）與全域同行程互斥鎖，所有觸發來源（NAS 排程、本機中介層、啟動追趕、手動回補、CLI）一律合流至同一套缺口計算與升冪重播邏輯。
   - 啟動追趕與例行補齊統一採用 **近 30 個日曆日缺口回溯窗（`maxLookbackDays = 30`）**，同時納入「完全缺失交易日」與「主副表不完整交易日」，由舊至新冪等補齊。
   - 實作 **台股盤後兩階段容錯收斂（Phase 1 收盤價量與淨值 $\ge 14:40$ 台北時間；Phase 2 完整籌碼／融資／借券 $\ge 16:30$ 台北時間）**，唯有全段資料達完整性門檻才推進台股水位線；未達完整前受每軌每日最多 4 次冷卻重試配額節制。
   - NAS 自治排程器廢除跨市場共用單日鎖，改為 **分軌獨立水位線狀態機**（`twDaily`、`usDaily`、`macro`、`weekly` 四軌各自追蹤水位線、狀態、錯誤與當日重試次數），並透過 `/healthz` 完整暴露健康遙測。
3. **靜態 JSON 市場快取 Expand–Contract 正式退役（SQLite-Only Sync Telemetry SSOT）**：
   - 先擴充 `/api/market/sync-status` 同步狀態契約，完整供應各軌道最新結算日、健康度、缺口數、進行中旗標與每週任務狀態（Expand）。
   - 將頂部同步狀態徽章與排程管理控制台全數遷移至 SQLite 同步狀態 API，移除應用程式啟動時的靜態 JSON 巨檔水合與 IndexedDB 單根覆寫，並讓前端啟動追趕掛鉤於背景追趕進行期間自動輪詢直至完成並刷新畫面（Migrate）。
   - 正式移除過期靜態市場快取讀寫預設路徑，修正靜態伺服器對 JSON 資產禁止回傳一年期 `immutable` 快取頭，並於架構適應度靜態守門強化全站禁令防止靜態快取路徑回流（Contract）。
4. **Card 01 盤中真實量價縫合（相容 Spec 0245 零量防禦契約）**：
   - 擴充即時報價解析契約，自 Yahoo Finance 與 TWSE 報價回應完整提取當日盤中 `open`、`high`、`low`、`volume`（及 TWSE `transactions`）。
   - 主力戰情室 `Card 01` 在盤中縫合當日 K 棒時，優先填入真實盤中開高低與成交量（不再硬塞 `volume = 0` 平盤十字線），使成交量與主圖即時反映當日實況；同時完整保留 Spec 0245 既有零量定錨防禦（`isVolumeAnchoredToPrevClose`），當上游報價確實未提供有效成交量時安全退回前一已結算交易日。

## User Stories

1. **NAS 24/7 長駐自動推進**：作為 QNAP NAS 系統維運者，我希望美股清晨同步與台股午後收盤同步彼此獨立互不鎖死；即使週五或國定假日前後上游延遲發布籌碼，系統也能在同日自動按兩階段容錯重試至完整結算，並在 `/healthz` 清楚看到四條軌道的最新水位線與缺口數。
2. **開機自動自癒近 30 日斷層缺口**：作為本機與 NAS 使用者，當裝置關機數日或因網路中斷漏抓多個交易日（例如 11/20、11/23 及先前的週五／週一空洞）後重新開啟系統時，我希望追趕機制能自動偵測並依序補齊近 30 日內所有缺失與不完整交易日，待完成後前端自動更新狀態，不再停留在舊日期。
3. **消除靜態過期快取干擾與 IndexedDB 破壞**：作為投資研究者，我希望系統狀態徽章、排程面板與個股 K 線一律以即時 SQLite 湖倉為單一事實來源，開機不再下載過期靜態 JSON，也不會把原本完整的 250 日歷史 K 線快取覆寫為單筆舊報價。
4. **盤中檢視 Card 01 真實量價**：作為盤中看盤使用者，當台美股處於開盤交易時段時，我希望主力戰情室 `Card 01` 當日 K 棒顯示真實盤中開高低與即時成交量，而不是停留在前幾日結算量或顯示量為 0 的扁平線段；若個別標的確實查無即時量能，則維持 Spec 0245 的前收量能定錨防禦不產生誤導警報。

## Implementation Decisions

- **決策 1（缺口回溯窗 Q1A）**：開機追趕與例行缺口補齊統一採用 `maxLookbackDays = 30` 日曆日回溯窗；超出 30 日的歷史大範圍回補保留給顯式手動歷史回補指令，兼顧自癒能力與官方 API 禮貌頻率。
- **決策 2（靜態快取退場 Q2A）**：採 Expand–Contract 三階段漸進退役靜態 JSON 市場快取：先擴充 SQLite 同步狀態 API → 再遷移前端徽章、排程面板與開機啟動流程（刪除靜態快取水合與單根覆寫）→ 最後移除殘留靜態快取依賴並鎖入架構適應度靜態守門。既有 CLI 腳本入口維持薄包裝向後相容。
- **決策 3（Card 01 盤中實量與零量相容 Q3A）**：即時報價型別擴充可選欄位 `open`、`high`、`low`、`volume`、`transactions`；當盤中報價提供有效正成交量與價位時，主 K 線縫合真實 OHLCV；若缺失或為 0，則保留 Spec 0245 `isVolumeAnchoredToPrevClose` 退回定錨行為。
- **決策 4（台股兩階段盤後收斂與重試配額 Q4A）**：台股收盤後分兩階段檢核（14:40 後允許先寫入價量與 ETF 淨值；16:30 後要求籌碼、融資與借券齊備才標記完整並推進水位線），單軌每日重試上限為 4 次（搭配冷卻間隔）。歷史補抓日（`< twLatest`）針對 TPEx OpenAPI 僅支援當日快照之物理限制採 TWSE 全量底線（`>= 900`），最新結算日維持全市場雙交易所底線（`>= 1500`）。
- **決策 5（零外部依賴 KISS 邊界）**：全程沿用 Node 22 原生 `node:sqlite`、原生定時器與既定單一行程架構，不導入 Redis、BullMQ 或額外背景微服務。

## Testing Decisions

所有驗證嚴格落於專案既有三條公開介面測試縫隙（Test Seams），依 TDD 紅－綠－重構循環執行，不依賴真實外網即可 100% 離線回歸：

1. **Seam 1（後端湖倉協調、NAS 分軌排程、中介層與架構守門）**：驗證統一結算時鐘與休市日曆、空表陳舊偵測、歷史補抓日覆蓋底線、三組跨模組契約、同行程全域互斥鎖、30 日缺口升冪補齊、台股兩階段容錯與 4 次重試配額、NAS 四軌獨立水位線狀態機、`/healthz` 遙測欄位、靜態 JSON 禁止 `immutable` 快取頭及架構守門禁令。
2. **Seam 2（前端同步狀態消費、排程面板與開機追趕輪詢）**：驗證 `MarketSyncStatusBadge` 與 `MarketScheduleHubSection` 消費 `/api/market/sync-status`、以及 `useMarketCatchupSync` 輪詢控制器於追趕進行中持續輪詢並於完成時觸發單次回呼與事件通知。
3. **Seam 3（即時報價 OHLCV 提取與 Card 01 盤中縫合回歸）**：驗證 `parseYahooQuoteResponse` 與 `parseTWSEDayAllResponse` 提取盤中真實 OHLCV 及防禦降級；驗證 `generateAiForceReportFromCandles` 縫合真實量價並 100% 保留 Spec 0245 `isVolumeAnchoredToPrevClose` 零量定錨保護。

## Out of Scope

- 不導入任何外部排程器、訊息佇列或第三方套件（Redis、BullMQ、cron 外部服務等）。
- 不處理跨裝置個人交易帳本雲端同步（已歸檔於既有技術債）。
- 不重寫財報季報（120 日 TTL）或題材催化劑（24 小時快取）既有抓取邏輯。
- 不移除既有的台／美日更命令列腳本入口（保留為薄包裝向後相容）。
- 不於本次迭代自動推送 Docker Hub 映像（待 PR 合併後依既有容器發佈流程辦理）。
