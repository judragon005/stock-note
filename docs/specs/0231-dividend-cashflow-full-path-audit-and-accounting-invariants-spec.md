# Spec 0231: 股利日誌與被動現金流全路徑帳務不變量修復與真實整合測試規格

## Problem Statement

身為台美股跨市場、多券商帳戶的長期實戰投資人，在使用「股利日誌與被動現金流全景」頁面進行現金流規劃、質押利差評估與除息對帳時，面臨以下帳務失真與測試盲區：

1. **跨帳戶與跨市場資料洩漏**：切換單一券商帳戶時，應收股息計算仍混入其他帳戶的交易股數與已入帳紀錄；無 `accountId` 的資料會穿透所有帳戶過濾器；全部帳戶模式下同名標的持倉會互相覆寫，導致 YOC 與「已結清部位」狀態錯亂。
2. **美股未乘匯率與成長股假配息**：12 個月現金流預測與未來股利推算將美股美元股價 1:1 直接當作台幣計入（少算約 32 倍），且未配息成長股（如 NVDA、TSLA）會被強制套用 4% 夏季假殖利率，產生虛假現金流。
3. **除息後清倉漏算與一鍵入帳重複記帳**：在除息日當天或之後賣光持股，應收股息直接蒸發；點擊一鍵入帳時，若來源為現有預約交易會重複新增第二筆 `DIVIDEND` 交易，且遺漏券商帳戶歸屬與二代健保稅額。
4. **時區跨日偏差與月配息視窗碰撞**：混用 UTC 與台北當地時間，導致每日凌晨 `00:00~07:59` 狀態機轉移慢一天；月配息 ETF 上期發放日若晚於下期除息日，登錄上期股息會誤殺下期應收。
5. **三方口徑分裂與假值誤導**：KPI 卡片（TTM 利差錯減選定年份股利、未接線匯費、誤計健保警示筆數）、月度長條圖（`GROSS` 模式仍顯示「實領入帳」與淨額明細、遺漏 `DUE_FOR_RECONCILIATION`）與歷史明細表（YOC 定義衝突、對帳與圖表匯率口徑不同、雙重渲染 `virtual_` 與原交易、美股環境仍推薦台股 ETF `00687B`/`00635U`）彼此矛盾。
6. **假綠燈測試風險**：現有測試多數自行複製業務邏輯或僅用字串渲染與過寬斷言（如 `toBeGreaterThan(0)`），無法攔截元件接線遺漏與單位換算錯誤。

---

## Solution

以「單一事實來源（SSOT）」與「帳務不變量守恆」為核心，針對股利與現金流全路徑進行系統性修復：

1. **建立複合主鍵隔離模型**：全面以 `(market, accountId, symbol, exDate)` 作為應收股息計算、已入帳去重與持倉對照的複合鍵，確保跨帳戶、跨市場嚴格隔離，且明確區分未指定帳戶資料的歸屬。
2. **補齊除息基準日快照與交易狀態機閉環**：即使投資人在除息後全數賣出清倉，仍依除息前一刻 ($T_{\text{ex}-1}$) 的實質持股計算應收股息；一鍵入帳統一依來源狀態執行「更新原交易」或「帶完整 `accountId` 與稅費新增交易」，杜絕重複記帳。
3. **統一匯率、稅費與台北時區日期基準**：為現金流預測與未來股利推算補齊 `usdToTwdRate` 匯率換算與美股 30% 預扣稅邏輯；移除對不配息成長股的預設夏季假殖利率；全面改用當地（台北）日期字串並支援跨午夜更新。
4. **收斂三方統計口徑與清除硬編碼假值**：統一 KPI、月柱圖與對帳明細表的匯率、稅費、YOC 標籤與 `GROSS`/`NET` 顯示語意；將硬編碼行事曆與股利假資料標記真實來源或移除未經實證的推估；補齊 `DUE_FOR_RECONCILIATION` 圖表呈現與 `totalWireFeesTWD` 接線。
5. **以最高層測試縫隙（Test Seams）建立真實整合測試**：淘汰複製邏輯的假綠燈測試，改由「應收與現金流引擎輸出縫隙」與「完整掛載的視圖元件互動縫隙」進行端到端紅-綠驗證。

## User Stories

1. 作為長期實戰投資人，我希望在切換特定券商帳戶檢視股利日誌時，應收股息、歷史實領與持股成本僅計算該帳戶的交易與部位，以便精準核對單一券商的實際入帳金額。
2. 作為同時持有同檔台股於兩個不同券商帳戶的投資人，我希望在「全部帳戶」模式下不會發生同代號持倉互相覆寫，以便正確顯示各帳戶對應的 YOC 與持倉狀態。
3. 作為同時投資台股與美股的投資人，我希望在 12 個月現金流預測月曆與未來股利推算中，美股股利能正確乘上 `usdToTwdRate` 並扣除 30% IRS 預扣稅後再加總至台幣現金流，以便掌握真實的台幣月度被動收入。
4. 作為持有不配息美股成長股（如 NVDA、TSLA）的投資人，我希望系統不會憑空捏造 4% 夏季現金股利，以便避免被虛假的預期現金流誤導生活費覆蓋率評估。
5. 作為在除息日後、發放日前賣光持股的投資人，我希望系統仍能依據除息前一日的持股紀錄追蹤該筆在途應收股息，以便確保每一筆應得股息都有入帳而不漏領。
6. 作為使用「一鍵入帳」功能核銷在途股息的投資人，我希望點擊入帳後系統能自動辨識該筆應收是否已存在預約交易並執行更新而非重複新增，且正確保留原本的券商帳戶與二代健保/預扣稅額，以便維持帳本零重複。
7. 作為持有月配息 ETF（如 00929）的投資人，我希望上個月配息的入帳紀錄不會因發放日與下個月除息日重疊而誤判下個月應收已入帳，以便準確追蹤連續每月的配息進度。
8. 作為在凌晨 00:00 至 07:59（台北時間 UTC+8）開啟系統的投資人，我希望除息日與發放日狀態轉移（如 `UPCOMING_EX` 轉 `PENDING_PAYMENT`）與當日一致，不因 UTC 時差而慢一天。
9. 作為使用質押槓桿的投資人，我希望在 TTM 近 12 個月滾動現金流卡片中看到的「扣除質押利息淨現金流」，是以 TTM 近 12 個月股利（而非切換後的歷史單一年度股利）扣除質押利息，以便正確評估當下的槓桿利差。
10. 作為切換「稅前應發 (GROSS)」與「稅後實領 (NET)」模式的投資人，我希望月度長條圖的 Hover 提示框與無障礙標籤文字與金額口徑完全一致（GROSS 顯示應發毛額與待入帳毛額），以便不產生加總對不起來的困惑。
11. 作為需要核對已到期應收股息的投資人，我希望處於 `DUE_FOR_RECONCILIATION` 狀態的款項能同步反映在月度現金流圖表中，且不會在應收行事曆與歷史明細表中同時以不同 ID 重複出現，以便清楚執行單一來源對帳。
12. 作為關注交易摩擦成本與二代健保的投資人，我希望 KPI 卡片能正確顯示台股累計匯費（`totalWireFeesTWD`），且單筆健保補充保費警示僅計算實際在途且達門檻（$\ge 20,000$ 元）的台股事件。
13. 作為同時檢視貢獻排行卡與歷史明細表的投資人，我希望「累計 YOC」與「單次年化 YOC」有明確的名稱區分與一致的計算基準，以便不被兩個不同數值的「YOC」混淆。
14. 作為僅檢視美股市場的投資人，我希望系統不會顯示硬編碼的台股 ETF（00687B、00635U）活水建議或硬套「已扣除二代健保」，以便獲得符合當前市場情境的真實摘要。
15. 作為經常編輯質押紀錄或使用搜尋框對帳的投資人，我希望在變更質押借款或輸入代號搜尋時，應收利息與對帳小計面板能即時同步過濾與更新，且空資料時有清楚的空狀態引導。

## Implementation Decisions

1. **跨帳戶與跨市場嚴格隔離（引擎層與視圖層）**
   - 應收股息計算引擎新增 `selectedAccountId` 與複合分組鍵 `(market, accountId, symbol)`，並確保只採用與當前過濾範圍匹配的交易計算除息前一日持股與已入帳比對；未帶 `accountId` 的資料在指定單一帳戶時必須排除，不得穿透洩漏。
   - 歷史明細表與貢獻排行卡建立複合鍵查找或依明細所屬帳戶對應持倉，解決 `ALL` 模式下同代號多帳戶持倉覆寫問題。

2. **除息清倉快照與交易去重精準化**
   - 應收股息計算不再僅依賴「當前剩餘股數大於 0 的持倉清單」，改為掃描所有在相關除息事件前一日 ($T_{\text{ex}-1}$) 持有正股數的標的（含已結清部位），確保除息後清倉之合法應收股息不遺失。
   - 已入帳比對（`isAlreadyLogged`）優先以精確的 `exDate` 鍵值或嚴格配對視窗比對（區分同標的相鄰期次），解決月配息 ETF 跨期重疊誤殺與延遲入帳重複計算問題。

3. **一鍵入帳狀態機收斂與雙重渲染消除**
   - 一鍵入帳處理器依應收項目來源區分路徑：若源自現有預約交易，更新原交易日期、狀態、稅費與帳戶歸屬；若源自外部/官方行事曆預測，則帶入完整的 `accountId`、正確計算的 `tax`（含台股二代健保與美股 30% 預扣稅）及 `fee` 建立新紀錄。
   - 統一應收項目在途視圖與已結算歷史流水表的邊界：已入帳流水表僅呈現已完成交割的實領紀錄，未入帳與待對帳項目統一歸口於在途應收/對帳專區，消除 `virtual_` 與原交易 ID 並存造成的雙重渲染。

4. **美股匯率換算、稅費一致化與移除假配息**
   - 12 個月現金流預測介面納入 `usdToTwdRate` 參數，於計算美股預期配息時乘上匯率並套用正確稅後比例；取消無歷史配息且非已知配息標的之「預設夏季 4% 假殖利率」回退，對不配息成長股誠實回傳 `0` 預期配息。
   - 未來股利推算函式補齊匯率參數與美股 30% 預扣稅計算，並統一自訂未來交易與一般除息事件的健保與匯費規則；移除硬編碼之特定個股（如 `2890`）2% 配股假設，並將內建靜態除息行事曆標記為離線/推估來源而非 `LIVE_API`。

5. **當地時區日期工具與統計口徑對齊**
   - 全域統一使用台北當地時間格式產生 `YYYY-MM-DD` 日期字串與加減日運算，消除 UTC 與本地時間跨日 ±1 天誤差，並確保長時間開啟頁面跨午夜後狀態可正確刷新。
   - KPI 卡片的 TTM 利差改以 `trailing12mDividendsTWD` 減去質押利息；接線 `totalWireFeesTWD` 並修正 `nhiAlertCount` 過濾條件（僅計在途應收台股）。
   - 月柱圖於 `GROSS` 模式同步切換標籤文字、明細金額與無障礙描述為應發毛額，並納入 `DUE_FOR_RECONCILIATION` 狀態項目；明確標註「累計 YOC」與「年化 YOC」區別，並統一對帳與圖表的匯率換算基準。
   - 依 `market` 與實際持倉狀態動態呈現 Zavy 策略摘要與稅務說明文字，移除跨市場硬編碼台股代號文案。

## Testing Decisions

1. **測試設計原則（行為導向、零邏輯複製）**
   - 嚴禁在測試檔內複製產品程式碼邏輯進行自證；所有測試必須直接呼叫公開引擎函式或透過 DOM 掛載完整視圖元件（支援點擊、輸入、過濾切換與回呼驗證），驗證外部可觀測行為與帳務守恆不變量。
   - 嚴禁使用 `toBeGreaterThan(0)` 等寬鬆斷言掩蓋單位錯誤，所有金額與匯率計算必須驗證精確數值（誤差範圍僅限四捨五入至整數 $\pm 1$）。

2. **最高層測試縫隙 (Test Seams)**
   - **縫隙一（核心帳務與現金流引擎縫隙）**：針對應收股息計算引擎、12 個月現金流預測引擎與股利聚合器進行輸入/輸出契約測試，覆蓋雙帳戶隔離、美股匯率與 30% 稅、除息後清倉、月配息期次重疊、UTC+8 跨日邊界與成長股零假息。
   - **縫隙二（股利日誌視圖整合縫隙）**：直接掛載主視圖元件與子元件（搭配 React Testing Library / DOM 事件模擬），驗證帳戶/市場/年份/搜尋過濾、GROSS/NET 切換、一鍵入帳去重回呼、KPI/圖表/對帳明細三方加總一致，以及空狀態渲染。

3. **既有測試清理與先例**
   - 清理現行測試中自行重寫業務邏輯的假測試、過時未使用的 Props 傳遞與單一月份不足的失真 Mock 資料，並補齊高風險未測函式（如未來股利推算與除息參考價計算）與快取驅逐邏輯測試。
   - 參照本專案既有的整合測試風格（直接引入元件並驗證渲染結果與狀態變更回呼）。

## Out of Scope

1. 不包含外部券商 API（FinMind / FMP / 交易所）之即時網路爬蟲協議重構或新增付費資料源整合。
2. 不修改股利日誌以外之其他獨立分頁（如投資組合總覽、技術分析儀表板、行為審計工作區）的 UI 排版與計算邏輯。
3. 不變更 LocalStorage 既有資料儲存格式之破壞性遷移（保持向後相容既有使用者儲存的交易與質押紀錄）。

## Further Notes

- 本規格對應專案前期對「股利日誌與被動現金流全景」之全路徑鑑識結果（含 3 項 P0、12 項 P1、9 項 P2 與 5 項 P3 項目），建議實作時依 **波次 1（P0 帳務隔離與匯率/清倉修復）➔ 波次 2（P1 狀態機與口徑對齊）➔ 波次 3（P2/P3 假值清除與完整 DOM 測試補齊）** 分批透過獨立分支與 PR 交付。
