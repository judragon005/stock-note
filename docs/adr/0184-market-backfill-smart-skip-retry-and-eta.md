# ADR 0184: 台股歷史回補智慧快取略過、指數退避重試、盤中時間守衛與 ETA 預估架構決策 (Market Backfill Smart Skip, Retry & ETA Engine)

- **狀態**: `ACCEPTED`
- **日期**: 2026-10-16
- **關聯規格**: [Spec 0184](../specs/0184-market-backfill-smart-skip-retry-and-eta-spec.md)
- **決策者**: Antigravity Core Team


---

## 1. 背景與問題情境 (Context)

在台股歷史全市場回補管線（Spec 0168 / Spec 0170）實裝後，實際運行時暴露出五大穩定度與效能瓶頸：
1. **上午 10:00 盤中啟動回補時**：因台股盤後日報於 15:30 始結算，系統請求 TWSE 查無資料，將今天誤判為「[休市日] 略過」，浪費 1 日天數配額且語意混淆。
2. **缺乏本地資料庫已在庫跳過**：每次回補 250 天，即使本機 SQLite 已經完整存有過去 200 多天數據，系統仍盲目發送 1,000 次 HTTP 請求，耗時近 50 分鐘。
3. **無重試機制造成偽成功**：在 2026-08-27 遭遇櫃買中心 20 秒逾時（Timeout）時，系統直接吞掉錯誤跳過 TPEx 1430，該次僅解析 1,365 檔（上市側）仍輸出成功。實測既有上櫃股票列因 UPSERT 保留，未遺失；但對原本無資料之日期會形成單邊缺失。
4. **候選日期未載入休市日曆**：未排除國慶日、中秋連假，造成無效請求。
5. **使用者無法預期耗時 (缺少 ETA)**：終端機與 UI 僅顯示天數與百分比，未估算剩餘時間；Vite proxy 轉發外部報價若遇網路中斷則噴發整頁紅字堆疊追蹤。

## 2. 決策考量與方案對比 (Decision Drivers & Trade-offs)

### 方案 A：引入分散式隊列框架（如 BullMQ / Redis / Cron 外部守護進程）
- **優點**：架構高度解耦，具備專業的 Job 隊列、Retry 與進度通知。
- **缺點**：嚴重違反 KISS 原則與免費額度約束，大幅增加系統依賴與本機資源佔用，過度工程化。

### 方案 B (採用)：基於現有 CJS 腳本與 SQLite 縫隙的手術刀式極簡升級
- **優點**：
  1. **零外部依賴**：查詢 `daily_candles` 當日 4 碼普通股筆數（≥ 1,800）與 `tw_institutional_chips` 筆數（≥ 2,000），兩者皆達標即秒級跳過。不採總筆數：該表同日混存美股代碼與 TPEx 權證，總數每日浮動 6,300~8,500。
  2. **盤中時間守衛**：當前本地時間 `< 15:30` 時候選起始日自動推至昨日（T-1），徹底消除無效請求。
  3. **指數退避重試**：將 `sync-tw-market.cjs` 現有的 `retryFetch` 統整共用，遇 Timeout 自動重試 3 次，拒絕單邊撕裂偽成功。
  4. **輕量 ETA 算力**：利用 `(total - done) * (elapsed / done)` 產出即時預估剩餘時間與完成時刻，同步更新終端機與 UI。
  5. **Vite 代理降噪**：在 `vite.config.ts` 的 proxy `onError` 攔截連線重置，安靜記錄 warning。
- **缺點**：需在 CJS 腳本中細緻維護時區與時間邊界。

---

## 3. 架構決策 (Decision)

決定採用 **方案 B**，落實以下架構規範：
1. **盤中時間定錨**：重用 `trading-calendar-engine.cjs`（`isTwTradingDay` / `getPreviousTradingDay`），15:30 前以前一交易日為起始日；日曆為休市唯一權威。
2. **Smart Cache Skip**：在 `fetchAndIngestTwDailyData` 入口處以普通股數＋籌碼數雙門檻判定，達標立即回傳 `cached: true`，不發起 HTTP 請求與 3 秒等待。
3. **指數退避重試與原子完整性**：統一使用 `retryFetch`（重試 3 次，延遲 2 秒遞增，僅限暫態錯誤）；單邊缺失或重試失敗之日期列入 `failedDates`，嚴禁偽成功。
4. **雙端 ETA 呈現**：`backfillGlobalStatus` 暴露 `estimatedRemainingMs` 與 `etaFormatted`，終端機與前端 UI 即時呈現預計完成時間。
5. **兩市場過濾對齊 (權證排除)**：TPEx 1430 解析時過濾排除 6 碼 7 開頭之權證標的，與 TWSE `ALLBUT0999` 標準完全對齊，精簡 70% 無效記錄。
6. **KISS 原則邊界**：不增加中途停止按鈕，任務具備極速秒跳特性，保持最精簡架構。

---

## 4. 影響評估 (Consequences)

### 正向影響 (Positive)
- **回補效率提升 100 倍**：若已有 240 天資料，回補 250 天只需檢查 10 天，耗時從 50 分鐘劇降至 30 秒內。
- **零單邊資料撕裂**：彻底杜絕「有上市無上櫃」或「有籌碼無日 K」的不一致缺陷。
- **開發體驗與使用者透明感**：消除紅色錯誤噪音，精確掌握回補進度與剩餘耗時。

### 負向影響與防禦 (Negative & Mitigations)
- **強制重補需求**：若使用者確實需要強制覆寫某日已在庫資料，新增 `--force` 旗標以跳過 Smart Cache Skip 檢查。
