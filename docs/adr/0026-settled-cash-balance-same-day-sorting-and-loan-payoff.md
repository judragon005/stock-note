# ADR-0026: 實質已交割可用現金隔離、同日金流雙向時間軸排序與質押設質規費還款總額整併

## 狀態 (Status)
已採納 (Accepted)

## 上下文 (Context)
1. **可用現金提早計入未來款項**：`calculateAccountBalances` 引擎原先將所有流水無條件累加，導致未來尚未發放的股息（如 2026-10-01 泰銘股息）與 T+2/T+1 待交割在途買進款提早計入交割戶當前可用現金餘額。
2. **同日金流「新 ➔ 舊」排序順序顛倒**：在「新 ➔ 舊」模式下，同日後發生的再投資買進扣款應該排在上方，先發生的股息入帳排在下方。
3. **預扣稅費缺乏專屬徽章**：被渲染為灰色「其他」徽章。
4. **質押還款總額計算重複且佈局零散**：質押借款還款總額重複計算了設質規費，且設質規費外掛於獨立黃框。

## 決策 (Decision)
1. **實質已交割可用現金與在途款隔離**：
   - `calculateAccountBalances` 僅累計 `date <= todayStr` 且 `settlementStatus !== 'PENDING'` 之款項。
   - 引入 `pendingSettlementAmount` 與 `projectedBalance`，於交割卡片上展示黃色「在途待交割」標籤與預估交割後餘額。
2. **同日雙向動態時間軸排序**：
   - 「新 ➔ 舊」模式下：當天後發生的流出/買進扣款排在上方（較新），先發生的流入/股息入帳排在下方（較舊）。
   - 「舊 ➔ 新」模式下：當天先發生的流入/股息入帳排在上方（較舊），後發生的流出/買進扣款排在下方（較新）。
3. **正名專屬「🧾 預扣稅費」徽章**：
   - 將 `TAX` 類別或備註含預扣稅之項目渲染為玫瑰粉專屬徽章。
4. **質押三大規費防重複計算與黑底卡片深度整併**：
   - `calculateLoanInterestAndPayoff` 優先取細項之和，無細項則取 `pledgeFee`，還款總額精準為「本金 + 利息 + 規費」。
   - 將設質三大規費完整整併進黑色核心卡片中。

## 後果 (Consequences)
- **正面效益**：
  - 現金交割戶餘額真實反映已交割現金，徹底阻斷未來事件膨脹當前現金。
  - 時間軸檢視順暢直覺。
  - 質押借款結清還款總額與券商對帳單 100% 吻合，視覺整齊統一。
