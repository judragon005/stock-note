# 0228 ADR: 股利時序黑洞根除、生命週期狀態機與已到期待核對閉環架構決策 (Dividend Reconciliation Blackhole Elimination, Lifecycle FSM & Due Settlement Pipeline)

## 狀態 (Status)
`ACCEPTED` (目標版本: v9.20.1)

## 背景與問題脈絡 (Context)
使用者回饋在席持有 0056，官方除息日（2026-10-22）與發放日（2026-11-11）已過，但在歷史現金股利明細表中整年僅看得到 2 月份一筆，11 月入帳款項徹底神隱。同時卡片 3（待入帳除息股利）Badge 標示「4 筆待入帳」但金額卻顯示「+NT$ 0」，且與下方面板的「(0 筆待入帳)」嚴重矛盾。

經架構審查發現兩大深層真因：
1. **時序黑洞蒸發**：`receivableDividendEngine.ts` 原先寫死 `if (currentDateStr >= payDate) continue;`，一旦發放日邁過，系統判定已實質落袋而自待發放清單中剔除；若帳本尚未手動記帳，該款項既非待入帳亦非已入帳，徹底蒸發。且 `OFFICIAL_DIVIDEND_CALENDAR` 遺漏收錄 0056 除息日曆。
2. **KPI 卡片口徑與下方面板割裂**：卡片 3 統計筆數包含金額為 0 之幽靈應收記錄，且篩選狀態與下方列表不一致。父層寫死 `payDate > todayStr` 過濾，扼殺明細表中未結算款項之呈現。

## 決策 (Decision)
1. **主流 ETF 官方除息日曆常態庫補齊**：
   - 於 `OFFICIAL_DIVIDEND_CALENDAR` 增補 `0056`（2026-10-22 除息，1.07 元，2026-11-11 發放）及主流 ETF 常態行事曆。
2. **除息在席持股容錯回退防禦**：
   - 於 `calculateReceivableDividends` 中強化除息在席股數解析：當歷史交易推估股數因時序未歸檔為 0 但庫存持股大於 0 時，安全回退採納在庫持股，杜絕金額為 0 之幽靈應收記錄，同時維持 `Ticket #005` 排除除息日後買進者之約束。
3. **引入「已到期待核對入帳態 (`DUE_FOR_RECONCILIATION`)」**：
   - 擴充 `ReceivableDividendStatus` 支援 `DUE_FOR_RECONCILIATION`；發放日已過但尚未在帳本完成核銷之除息款項，嚴禁丟棄，自動提升為待核實態。
4. **卡片 3 筆數與金額數學閉環對齊**：
   - 統一以 `activeReceivables`（實領淨額 $> 0$ 且狀態為未結算/待核對）為單一真理源，卡片 3 主金額與 Badge 筆數達成 100% 數學一致，並與下方待入帳專區同步。
5. **歷史明細表待核實專區與「一鍵確認入帳」閉環**：
   - 明細表頂部增設「⚡ 官方已發放·待核對入帳款項」高亮專區，展示除息日、發放日、除息時持有股數、每股配息與實領淨額。
   - 提供「確認網銀已入帳」按鈕，串接 `App.tsx` 中的 `handleInstantSettleDividend`，一鍵自動寫入標準 `DIVIDEND` 交易記錄並同步現金流水帳。

## 後果與影響 (Consequences)
- **正面效益**：
  - 徹底終結發放日邁過後股利紀錄憑空消失的時序黑洞，投資人隨時能清晰掌握已除息但在途或待對帳款項。
  - 卡片 3 與下方面板 100% 數據閉環，根除 Count=4 但 Sum=0 的荒謬視覺矛盾。
  - 提供秒級一鍵記帳體驗，自收到網銀通知至完成帳本記錄僅需 1 次點擊。
  - 全專案 2,220 個單元測試 100% 通過，TypeScript 編譯零錯誤。
