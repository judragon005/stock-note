# ADR 0120: 台美雙市場全量籌碼零遺漏、雙軌原子合流與真實 20D CMF 入庫防禦架構

## 狀態
已通過 (Accepted) - 2026-09-12

## 上下文 (Context)
使用者回報重要系統缺陷與需求：
1. **籌碼動能資料停在 9/9 斷層**：系統啟動時未如期更新至 9/11，9/10 資料空白。經排查為 `vite.config.ts` 中的 Proxy 路由規則，`/api/twse` 匹配前綴優先於 `/api/twse-www`，導致上市日報請求被改寫為 `-www/rwd/zh/fund/T86...` 打往 OpenAPI 產生 404 (nginx)，導致上市資料 100% 遺失。
2. **單邊殘缺日報污染與降級死鎖**：因僅有上櫃 894 檔資料，多維哨兵正確判定殘缺而拒絕寫入快取，但因缺乏指數退避重試與自動洗滌殘缺快取機制，系統陷入永遠回退 9/9 最後已知有效快取的狀態。
3. **美股籌碼缺乏真實入庫管道**：美股標的過去使用 `Array.from({ length: 20 })` 進行常態分佈虛擬模擬日 K 計算 CMF，違反使用者「攸關真實買賣與避坑決策，不容任何模糊或不確定空間」的核心原則。

## 決策 (Decision)

1. **Vite Proxy 路由優先權修正**：
   - 將 `vite.config.ts` 中 `'/api/twse-www'` 明確排在 `'/api/twse'` 前方，杜絕 Prefix Shadowing，確保上市大盤日報正常取得 200 OK（1,300+ 檔）。

2. **雙哨兵互補檢驗與全市場深度校驗**：
   - 升級 `isInstitutionalReportComplete` 哨兵合規邏輯：
     - 上市龍頭台積電 (`2330`) 必須存在。
     - 上櫃龍頭群聯 (`8299`) 必須存在。
     - 全市場深度總檔數 $\ge 1,800$ 檔。
     - 前 50 大活躍法人買賣超成交張數非零。

3. **台股雙軌原子合流 (Atomic All-or-Nothing)**：
   - 於 `fetchCombinedTwseAndTpex` 實施原子合併：上市 (TWSE) 與上櫃 (TPEx) 任一市場拉取失敗或未達雙哨兵門檻時，一律視為未發布完畢，嚴禁單邊殘缺資料寫入快取。
   - 實作具指數退避之 `fetchWithRetry`（最大重試 3 次，遇 404 即時中斷）。

4. **歷史快取自癒洗滌 (Cache Wash)**：
   - 讀取本地快取時全面套用雙哨兵檢驗。若歷史快取存在僅有單邊市場的殘缺紀錄，自動標記無效並自遠端全量增量重抓並覆蓋。

5. **美股真實日 K 存入 IndexedDB 與真實 20D CMF 計算**：
   - 實作 `fetchUsMarketRealData`，對接 Yahoo Finance Chart API 抓取真實 3 個月日 K（OHLCV）。
   - 將美股真實日 K 持久化至 IndexedDB `ohlcvStore`。
   - 徹底拔除 `ChipsWorkspace.tsx` 中的虛擬模擬代碼，全面改由真實日 K 運算真實 20D CMF 與時序 flow。

6. **雙市場獨立健康指標 HUD 與一鍵全量重新同步**：
   - 籌碼工作區頂部提供台股（TWSE+TPEx 總檔數、更新日期）與美股（持倉標的 CMF 狀態、K線涵蓋期）之獨立健康徽章。
   - 新增「🔄 雙市場全量重新同步」按鈕，支援使用者手動觸發強制洗滌快取與全量回補。

## 後果與效益 (Consequences)
- **正面效益**：
  - 徹底解決 9/10、9/11 資料斷層，台股上市櫃 2,200+ 檔籌碼每日 100% 完整捕捉入庫。
  - 杜絕美股數學公式模擬日 K 假象，達成台美雙市場 100% 真實數據決策護城河。
  - 增強系統自癒能力，殘缺快取自動偵測並洗滌覆蓋。
- **維護約束**：
  - 未來擴充新市場或外部資料源時，必須嚴格遵守「全有或全無」原子性原則，嚴禁未經校驗寫入快取。
