# ADR-0003: V1.2 公司行動、基準日時序回溯與混合金融掃描架構

## 狀態 (Status)

Accepted (已核准) — 2026-08-20

---

## 背景與脈絡 (Context)

在台股與美股的長期存股與波段投資情境中，標的經常發生非典型買賣交易的「公司行動 (Corporate Actions)」：
1. **除權配股 (Stock Dividend)**：發放股票股利，持有股數增加，總投入成本不變，單位買入成本稀釋。
2. **股票分割與反分割 (Stock Split / Reverse Split)**：美股（如 NVDA 1 拆 10）與台股分割，持有股數依比例倍增或合併，總成本不變。
3. **現金減資與虧損減資 (Capital Reduction)**：現金減資退還本金（資本返還）並縮減股數；虧損減資彌補虧損僅縮減股數。
4. **現金增資認股 (Capital Increase)**：股東認購新股，增加持有股數並額外投入本金。
5. **歷史基準日判定需求**：使用者在補登除權息或減資時，無法輕易回憶「除權息基準日當日」自己究竟持有多少股，需系統自動依歷史時序推算。

---

## 決策 (Decision)

### 1. 擴充統一事件流模型 (Unified Event Stream Architecture)

**選擇**：將所有公司行動直接整合進統一的 `TradeType`：
`'BUY' | 'SELL' | 'DIVIDEND' | 'STOCK_DIVIDEND' | 'STOCK_SPLIT' | 'CAPITAL_REDUCTION' | 'CAPITAL_INCREASE'`，並於 `TradeRecord` 擴充 `ratio`, `cashAmount`, `exDate` 等選擇性欄位。

**理由**：
- **KISS 原則**：不另設「公司行動專屬資料表」，避免多表關聯與同步複雜度。
- **時序回放一致性**：所有交易與公司行動均作為「時間軸事件流」儲存，排序算法（`date ASC, createdAt ASC`）可單一適用。
- **儲存與備份無縫相容**：CSV / JSON 匯出匯入與 LocalStorage 存取延用單一流水帳介面，零架構破壞。

---

### 2. 時序回溯引擎與純函式股數累算 (`applyTradeToShares`)

**選擇**：
- 實作純函式 `applyTradeToShares(currentShares, trade)`，封裝單一事件對持有股數的增減/乘除公式。
- 實作 `getHoldingsAsOfDate(trades, targetDate, symbol)`，透過時序過濾（`date <= targetDate`）與回放，在 $O(N)$ 內精確重現基準日時點的有效持股。

**理由**：
- 將「股數異動計算」與「成本/損益會計計算」權責分離，消除重複的 switch-case 邏輯。
- 提供給 `TradeModal` 動態試算與 `CorporateActionScanner` 自動換算待配發股數與現金。

---

### 3. 資本返還與真實本金會計模型 (Capital Return & YoC Basis)

**選擇**：
- **現金減資**：退還之現金金額視為「資本返還 (Return of Capital)」，直接從總投入本金扣減（`totalCostBasis = Math.max(0, totalCostBasis - refund)`），並累計於 `totalCapitalReturned`。
- **成本殖利率 (YoC)**：計算公式為 `totalDividends / totalCostBasis * 100`。因 `totalCostBasis` 已扣減減資退款，真實反映剩餘在倉本金的現金流效益。
- **原始股數分離**：於 `HoldingPosition` 提供 `originalBuyShares`，在持股明細中將「原始買入股數」與「累計配股 (+股數)」分離呈現。

**理由**：
- 現金減資退回的是投資人原本投入的本金，若計入「已實現獲利」或「股息」，會嚴重扭曲報酬率與成本結構。
- 分離呈現原始股數與配股異動，讓長線存股者能清晰看見股權膨脹效應。

---

### 4. 混合雙軌金融資料掃描架構 (Hybrid Dual-Track Scanner)

**選擇**：在 `corporateActionScanner.ts` 採用「線上即時 API 優先 + 離線備援庫降級」架構：
1. **主軌**：透過 CORS 代理請求免費 Yahoo Finance Chart API (`events=div|split`)，即時取得台美股 5 年內除權息與分割歷史。
2. **副軌**：若網路逾時（4 秒）、無網路或跨域受限，自動平滑降級讀取內建 `BUILT_IN_EVENT_REGISTRY` 靜態事件庫。
3. **資料源標籤**：回傳之事件標註 `sourceType: 'LIVE_API' | 'FALLBACK_DB'`，UI 即時展示連線狀態徽章。

**理由**：
- 零外部付費 API Key 依賴，符合個人開源記帳軟體的零成本原則。
- 內建離線備援庫確保離線斷網情境下仍具備熱門標的（如台積電 2330、0050、00878、NVDA、AAPL 等）的展示與測試能力。

---

## 後續影響 (Consequences)

1. **模組擴展性**：未來若欲新增其他公司行動（如：換股合併、特別股贖回），只需擴充 `applyTradeToShares` 與會計 switch 分支，其他展示層無需大幅重構。
2. **效能影響**：持股計算與基準日回溯均為純記憶體陣列操作，千筆交易內運算耗時 < 2ms。
3. **維護建議**：`BUILT_IN_EVENT_REGISTRY` 適合作為測試與展示備援，長期歷史資料主要依賴線上 API 抓取與使用者手動微調。
