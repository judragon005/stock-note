# ADR 0189: 台美智慧回補增量缺口探測、零延遲快取跳過與自適應排程控制台

## 狀態 (Status)
已採納 (Accepted) - 2026-10-16

## 決策背景 (Context)
在先前實裝的台美歷史雙軌回補管線中，日常運作暴露出嚴重的效能瓶頸與使用者等待時間浪費：
1. **無智慧缺口探測**：每次手動或背景啟動回補時，系統固定強制產生 250 個法定交易日，無論資料庫是否昨日才剛同步過，皆需耗費 30~50 分鐘重跑 250 天。
2. **偽快取略過與時間浪費**：主迴圈冷卻邏輯缺少 `!res.cached` 檢查，導致即便是 100% 已在資料庫達標的歷史日，每一天依然強制沉睡 3 秒，250 天白白空等 12.5 分鐘以上。
3. **排程選單粒度僵化**：UI 僅提供 60/120/250 三檔，缺少最常用的「智慧補缺 (Auto Gap)」、「近 5 交易日 (一週)」與「近 20 交易日 (一月)」。
4. **美股全量連動過重**：每次回補美股均重跑全量隊列 bootstrap，無法輕量增量同步。

## 決策內容 (Decisions)
1. **實裝 SQLite 水位線缺口探測核心 (`detectTwDateGaps`)**：
   - 總控啟動前，比對法定日曆與資料庫日 K / 籌碼雙指標健康快取狀態，僅萃取出未達標之「缺漏交易日 (Gap Dates)」。
   - 若資料庫最新日已是最新且無缺口，回報「已在庫且達標，無需回補」，0 秒結束。
   - 若有缺漏（通常僅 1~3 天），精準針對該少數天數進行網路採集與入庫。
2. **真·零延遲快取跳過 (Zero-Delay Cache Skip)**：
   - 修正主迴圈：僅在發起實體外部網路請求且未命中快取時才執行 `throttleMs` 延遲。
   - 已在庫日 0ms 略過，250 天在庫檢測能在 0.5 秒內極速完成。
   - ETA 計算器排除快取日期的時間權重，預估時間精準反映真實待抓取負載。
3. **擴充排程控制台粒度並設「智慧自動補缺」為預設**：
   - UI 提供 `auto` (預設)、5、20、60、120、250 六檔。
   - Vite 中介層 `POST /api/market/backfill-all?days=auto` 原生支援智慧模式。
4. **美股日常增量模式連動**：
   - 在 `auto` 或短天期模式下，美股改跑 `--mode=daily` 增量同步，大幅減輕伺服器與本機負載。

## 後續影響 (Consequences)
- **正面效益**：
  - 日常盤後回補耗時由原本 30~45 分鐘驟降至數秒（僅抓最新 1~2 天）。
  - 已有完整歷史資料時，重新執行 250 天回補可在 1 秒內極速驗證完畢，不再無意義空轉。
  - 美股日常增量同步大幅減輕網路流量與記憶體消耗。
- **潛在權衡**：
  - 需依賴資料庫既有 `daily_candles` 與 `tw_institutional_chips` 索引進行缺口探測，已具備複合索引保障探測效能。
