# 0061. 減資多源去重、虛擬時序動態扣減與交易帳本股息淨額對齊

日期: 2026-09-01

## 狀態 (Status)

已接受 (Accepted)

## 背景 (Context)

在 9927 泰銘 2025 年減資換發與 2026 年配息補登流程中，系統暴露了以下核心會計計算與資料源整合缺陷：
1. **多來源減資重複抓取**：TWSE 官方 API 登記減資基準日為 `2025-09-15`（含退款），Yahoo Finance 則將反向分割登記在上市日 `2025-11-13`（無退款），因缺乏日期區間去重機制導致重複補登兩次減資，在倉股數被多扣減 2,828 股。
2. **智慧掃描虛擬時序漏扣減資**：`scanCorporateActions` 的虛擬時序池 `virtualTrades` 只累加配股/分割，漏掉減資扣減，導致次年除息持股被誤算為 12,829 股。
3. **歷史交易帳本重複扣稅**：台股現金股利 `TradeRecord.cashAmount` 已為扣除二代健保後實收金額，但 `TradeHistoryTable` 又再次扣減 `tax`，導致顯示金額比現金流水帳少扣一次健保費。
4. **減資比率精度誤差 (1 股誤差)**：使用 `0.2828` 簡化比率計算 10,000 股減資換發產生 7,172 股（少扣 1 股），未能對齊台灣集保官方 6 位精準比例 `0.2828051` 換發之 7,171 股（縮減 2,829 股）。

## 決策 (Decision)

1. **多來源減資合併與歷史重複防護**：
   - 在 `fetchLiveCorporateEvents` 中針對 $\le 90$ 天內同標的之減資換發進行去重合併，優先採用 TWSE/備援庫之官方基準日與退款金額。
   - 在 `isAlreadyRecorded` 中增加 $\le 90$ 天內同類型減資之重複入帳防護。
2. **虛擬時序動態扣減減資股數**：
   - 在 `scanCorporateActions` 中，未入帳之 `CAPITAL_REDUCTION` 生成虛擬交易推入 `virtualTrades`，確保後續配息回溯基準日持股之準確性。
3. **歷史交易帳本實收金額對齊**：
   - 在 `TradeHistoryTable` 中，台股現金股利優先採用已扣稅之 `cashAmount` 呈現結算金額，杜絕二次扣稅。
4. **官方精準減資比率升級**：
   - 官方備援庫升級為 6 位小數 `0.2828051`，確保 10,000 股減資精準銷除 2,829 股，買回 2,829 股後持股 100% 回歸 10,000 股。

## 後果 (Consequences)

- **正面影響**：
  - 徹底解決多資料源導致的減資重複補登問題。
  - 智慧掃描在倉時序回溯與除息計算 100% 吻合集保官方會計準則。
  - 歷史交易帳本與台股現金流水帳待交割金額完全一致。
  - 單元測試 386 題全數通過，`npm run build` 0 錯誤。
