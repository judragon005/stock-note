## 🎯 迭代背景與解決之痛點

1. **借貸入帳缺失導致現金餘額虛減**：
   使用者於 2026-07-28 辦理之股票質押借款，在先前版本中僅記錄了償還本金的現金扣款流水（`LOAN_REPAYMENT`），未記錄借款成立時的撥款入帳流水（`LOAN_DISBURSEMENT`），導致現金帳戶可用餘額被單向虛減。
2. **已歸還完成之借貸持續佔用看板且誤判追繳斷頭**：
   借貸本金全額償還（未還借款本金為 NT$ 0）後，系統仍持續以卡片形式展示於頂部看板。且計算引擎因分母為 0 回傳維持率 0.0%，觸發追繳斷頭紅燈警報，並持續顯示殘留的設質規費欠款（NT$ 53 / NT$ 54）。

## 🚀 本次交付核心改進

1. **新增借貸自動連動撥款入帳**：
   - `LoanModal` 新增「建立時自動於關聯帳戶記錄借款撥款入帳 (`LOAN_DISBURSEMENT`)」選項（預設開啟）。
   - 建立時自動產生以借款起日為準的正數現金流入，確保借貸成立與還款本利和的會計借貸平衡。
2. **歷史借款缺漏一鍵平帳機制**：
   - `CashLedgerWorkspace` 主動偵測具有還款但缺失借款入帳之歷史借貸（包含 2026-07-28 之永豐金質押）。
   - 看板頂部提供「⚡ 一鍵自動補登撥款入帳 (平帳)」按鈕，使用者點擊即可自動補齊 2026-07-28 之撥款入帳流水，可用現金瞬間平衡。
3. **進行中與已結清看板分流**：
   - 頂部風控看板僅渲染進行中借貸 (`activeLoans: principal > 0`)。若無未清償債務，顯示「🟢 目前無未結清之借貸或股票質押負債」安全看板。
   - 已還清借貸自動歸入專屬「📜 歷史借貸與質押已結清紀錄」可折疊清單，完整保留歷史初借額、起訖日、利率與原擔保品清單。
4. **零借款本金斷頭誤判防禦與規費清零**：
   - `calculatePledgeMaintenanceRatio`：未還本金歸零時回傳 `maintenanceRatio: Infinity`，狀態為 `SAFE` 且 `isMarginCall: false`，介面顯示「無負債 (安全)」。
   - `calculateLoanInterestAndPayoff`：本金歸零時應還款總金額、利息與規費精確歸零。
