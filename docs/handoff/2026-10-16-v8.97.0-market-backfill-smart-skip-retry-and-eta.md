## 1. 迭代背景與核心解決痛點

在台股歷史全市場回補管線上線後，使用者回報了五個關鍵實際運行痛點：
1. **盤中 10:00 啟動回補誤判休市**：盤後日報於 15:30 始結算，系統請求 TWSE 查無資料，將今天誤判為「[休市日] 略過」，浪費 1 天配額且語意混淆。
2. **缺乏本地 SQLite 已在庫快取跳過**：每次回補 250 天，即使本機已存有過去 200 多天數據，系統仍盲目發送 1,000 次 HTTP 請求，乾等 50 分鐘。
3. **收盤行情檔數 (~8,000) 與籌碼檔數 (~2,240) 的同日落差**：經底層資料庫審查證實，8,000 檔與 2,240 檔的差距**不是可轉債，而是櫃買中心 (TPEx) 6 碼以 7 開頭之認購/認售權證**（單日多達 5,500+ 筆），而 TWSE 上市側早已有 `ALLBUT0999` 排除權證，導致兩市口徑脫鉤。
4. **網路暫態逾時造成單邊偽成功**：如 2026-08-27 遭遇櫃買 20 秒逾時直接跳過，導致當天上櫃行情缺失卻輸出成功入庫。
5. **使用者無法預期耗時與連線中斷紅字**：無預計剩餘時間 (ETA)；Vite proxy 連線 Yahoo Finance 遭遇暫態 `ECONNRESET` 時噴發整頁紅色堆疊追蹤。

### 2.4 SQLite 雙指標健康快取秒級略過 (Ticket 04 & Code Review Auto-Fix)
- **代碼檔案**：[`scripts/market-sync/backfill-tw-history-web.cjs`](file:///d:/APP/股票紀錄/scripts/market-sync/backfill-tw-history-web.cjs)
- **實作重點**：
  - 快取憑證查驗 SQL：
    `SELECT COUNT(*) AS stockCount FROM daily_candles WHERE date = ? AND symbol GLOB '[1-9][0-9][0-9][0-9]';`

  - 放行門檻：`stockCount >= 1800 && chipCount >= 2000` 且未指定 `--force`。
