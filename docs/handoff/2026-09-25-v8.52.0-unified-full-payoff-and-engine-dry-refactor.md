## 2. 核心成果清單

1. **質押借貸 `FULL_PAYOFF` 統一委託核心會計引擎 (`applyDebtRepayment`) (Debt #0036)**：
   - 根除 PR #24 審查警示 W1：過往全額結清手動拼裝 62 行狀態與帳務，與部分還款之 `applyDebtRepayment` 形成危險的雙軌架構。
   - 重構 `CashLedgerWorkspace.tsx`，將 `FULL_PAYOFF` 統一流轉至 `applyDebtRepayment` 純函式引擎。
   - 確保所有質押還款路徑一律遵循嚴格的會計沖償優先序（利息 ➔ 規費 ➔ 本金）與現金流水帳產生邏輯，消除未歸還本金與應計費用失步風險。

2. **流通股數推導純函式集中化 (`deriveSharesOutstanding`) (Debt #0038)**：
   - 在 `src/engine/keyMetricsEngine.ts` 導出標準推導函式 `deriveSharesOutstanding(quarter)`。
   - 統籌收斂 `calculateFcfYield`、`calculateDcfValuation` 及 `AnalysisMetricView.tsx` 三處分散的股本除以面額 ($10) 之重疊算式。
   - 支援邊界值安全防禦：面對無效資本額、零股本或 NaN 時，安全回傳 `null`，杜絕 `Infinity` 或非預期崩潰。

3. **持倉雙階自然排序共用比較函式 (`compareHoldingsOrder`) (Debt #0001)**：
   - 新增 `src/utils/holdingsSort.ts` 模組，導出共用排序函式 `compareHoldingsOrder(a, b)`。
   - 集中定義標準雙階自然排序：第一階依市場分類（台股優先於美股），第二階依股票代碼自然排序（`localeCompare(..., undefined, { numeric: true })`）。
   - 同步收斂 `src/engine/calculator.ts` (後端計算聚合) 與 `src/components/HoldingsTable.tsx` (前端視圖呈現)，杜絕未來雙邊排序規則脫鉤。

4. **技術債看板系統性閉環維護**：
   - 更新 `docs/debts/README.md` 索引，將 Debt #0001, #0036, #0038 狀態更新為 `RESOLVED`，標註於 Spec 0139 / V8.52.0 解決。
   - 同步修正個別技術債文檔狀態與修復說明，維持零技術債漂移。
