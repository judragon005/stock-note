# 需求規格書 Spec 0219: 台美股機構級深度財報研究與實戰投資決策系統 (Institutional Equity Research & Decision System)

## Problem Statement

當前專案中的「個股分析（深度財報）」頁面，雖然具備基礎的季度財務三表與估值河流圖，但在面向機構投資人、專業分析師與實戰交易者的決策場景中，存在以下重大缺陷：
1. **只陳述表面數據，未穿透「財報沒說什麼」**：頁面缺乏本業純度（營業利益 vs 業外損益）拆解、營運槓桿係數 (DOL) 轉折、以及營收成長加速度（$\Delta \text{YoY}$）。投資人無法一眼洞察獲利暴衝是否來自一次性賣祖產，也無法識別成長動能已悄然見頂。
2. **估值模型停留在正向假設，未回答「現價是否已反映公司的好」**：現有 DCF 模型僅支援正向推導，容易流於主觀通靈。投資人迫切需要反向推導的「Reverse DCF（現價隱含 FCF 成長率）」與 Bull/Base/Bear 三情境安全邊際矩陣，客觀評估市場定價是否過度透支樂觀預期。
3. **資料庫存在嚴重資料孤島 (Data Silos) 與契約斷裂**：本地 SQLite 數據湖倉已完整入庫近 12 個月營收 (`tw_monthly_revenue`)、官方每日 PE/PB/殖利率 (`tw_valuation_daily`)、董監持股質押 (`tw_insider_pledge_records`)、官方產業分類 (`symbols_meta`) 與真實日 K 收盤價 (`daily_candles`)。但深度財報頁面完全未連通這些寶藏表，且因中介層回傳結構與前端 `Array.isArray` 契約不符，導致本地湖倉快取讀取 100% 失效，頻繁引發外部 API 限流與白畫面。
4. **資訊分散，缺乏買方機構級 Executive Summary 與決策閉環**：進入頁面後需在多個標籤間穿梭，缺少結論先行的總覽面板、100 分制 8 維度透明評分、實戰買進觀察區與論點失效條件；且非結構化質化資訊（法說會展望、預期差 Beat/Miss、反方紅隊挑戰）無法與本地量化數據協同閉環。

## Solution

依據 12 人虛擬買方研究團隊架構，恪守 KISS 原則與 Zero-Mock 協議，實施「本地確定性量化精算 + 外聯 AI 深度投研雙軌閉環」：
1. **修復湖倉讀取契約並貫通 5 大數據寶藏**：修復 `lakehouseFinancialClient` 陣列解析 Bug，一次性連通月營收（含 ATH 標籤）、官方估值、董監質押（點亮斷頭紅燈）、真實日 K 收盤價（注入河流圖歷史軌跡），徹底終結資料孤島。
2. **財報歷史深度擴充至 12 季與 20 季 (5 年)**：提供 `[ 8 季 | 12 季 | 20 季 (5年) ]` 分段切換器，滿足中長期景氣循環研究。
3. **深入財務鑑識與本業純度拆解**：提煉「本業獲利純度比率」、「營運槓桿係數 (DOL)」、「營收成長加速度 ($\Delta \text{YoY}$)」，並活化既有法務會計 7 大排雷燈與每股淨現金安全邊際。
4. **企業估值第一性原理升級**：導入 Reverse DCF 反向逆推現價隱含成長率，建立 Bull / Base / Bear 三情境合理價值區間與安全邊際 (Margin of Safety %)。
5. **頂部新增「01｜機構研究總覽 (Executive Summary)」**：包含 8 維度 100 分制透明量化評分、財報說了什麼 vs 沒說什麼對照卡、實戰買進區間與論點失效警戒。
6. **專屬「12 位分析師投研 Prompt 抽屜」與策略釘選回流**：本地零 Token 生成結構化投研 Prompt，支援複製至外部頂尖模型推演非結構化質化報告，並復用專案既有 `strategyPinEngine` 一鍵貼回釘選。

## User Stories

1. 作為機構投資人，我希望在進入深度財報時能看到結論先行的「01｜機構研究總覽」，以便在 3 秒內掌握核心投資論點、多空看點與 100 分制綜合評分。
2. 作為機構投資人，我希望查看透明的 8 維度評分權重（營收 15%、獲利與 ROIC 15%、現金流 15%、安全 10%、優勢 10%、產業 10%、估值 15%、催化劑 10%），以便量化評估企業體質而非依賴主觀直覺。
3. 作為基本面研究員，我希望系統能將歷史三表切換為「12 季 (3 年)」或「20 季 (5 年)」，以便觀察跨越完整景氣循環的財務結構變化。
4. 作為台股投資人，我希望在個股深度財報中直接看到近 12 個月營收趨勢、YoY、MoM 與是否創歷史新高 (ATH)，以便比對月營收高頻領先動能。
5. 作為財務鑑識專家，我希望系統明確拆解本業營業利益與業外損益（本業純度比率），以便識破靠賣地或轉投資一次性美化 EPS 的紙上富貴。
6. 作為賣方分析師，我希望看到營運槓桿係數 (DOL = 營業利益 YoY / 營收 YoY)，以便捕捉固定成本攤提跨越損益兩平點時的獲利非線性爆發轉折。
7. 作為買方 PM，我希望看到營收成長加速度（$\Delta \text{YoY}$ 二階導數），以便提前預警表面營收年增但成長動能已急遽放緩的失速風險。
8. 作為實戰投資者，我希望使用 Reverse DCF（現價隱含成長率）功能，以便一眼看出目前的市場價格到底隱含了未來每年幾 % 的自由現金流複合增長。
9. 作為價值投資人，我希望看到 Bull / Base / Bear 三情境的合理價值區間與安全邊際 (Margin of Safety %)，以便建立足夠防禦性的建倉邊界。
10. 作為技術分析與基本面兼修的交易員，我希望估值河流圖（PE/PB 河流）上能繪製出真實歷史股價的走勢紅線，以便直觀評估當前股價穿透河流的歷史相對位階。
11. 作為風控官，我希望系統能接通本地湖倉的董監質押率，當個股質押超過 50% 時自動亮起斷頭警戒紅燈，防止遭遇系統性流動性崩盤。
12. 作為風控官，我希望系統能接通內部人申報轉讓張數，當內部人單月大量減持時自動觸發籌碼鬆動警報。
13. 作為美股投資人，我希望查看美股科技股的高額股權激勵 (SBC) 佔營收比例，以便量化高管期權對普通股東實質權益的稀釋程度。
14. 作為使用者，我希望本地湖倉已快取的財報能瞬間載入（< 50ms），徹底杜絕每次重複請求外部 API 導致的 429 限流與白畫面。
15. 作為系統使用者，當非持倉股缺少即時報價時，我希望系統以湖倉最近收盤價為基準，嚴禁以 `100` 元假數字進行估值計算。
16. 作為投資人，我希望系統能在頂部清楚標記財報期間（如 2025Q3）、資料來源（Lakehouse / SEC EDGAR / FinMind）、計價幣別與單位，落實第一手數據透明度。
17. 作為專業研究員，我希望一鍵複製組裝好的「12 位分析師機構級投研 Prompt」，以便在外部最強 LLM 中推演法說會管理層語氣、TAM 與反方紅隊挑戰。
18. 作為實戰操盤手，我希望將外部 LLM 分析產出的標準 JSON 裁決塊一鍵貼回，釘選在深度財報頁面頂部，形成研究到交易的追蹤閉環。
19. 作為持股投資人，我希望決策框架能自動感知我的持有成本、未實現損益與部位佔比，給出個人化的持倉防禦或加碼建議。
20. 作為空手觀望者，我希望決策框架能給出客觀的合理買進區間、避免追價條件與假說失效條件。

## Implementation Decisions

1. **修復湖倉財報讀取與擴充 Schema (Lakehouse Contract Repair)**：
   - 修正 `lakehouseFinancialClient` 中的陣列判斷邏輯，使其兼顧 `{ symbol, count, financials }` 與 `{ data: financials }` 結構。
   - 解除後端 `limit=8` 預設截斷，支援查詢近 20 季全量歷史財報。
2. **多維數據湖倉端到端接通 (Five-Silo Bridge)**：
   - 在深度財報載入時，透過專案既有 `loadSymbolFullLakehouseData` 並行提取月營收 (`tw_monthly_revenue`)、官方估值 (`tw_valuation_daily`)、董監質押 (`tw_insider_pledge_records`)、產業分類 (`symbols_meta`) 與日 K 線 (`daily_candles`)。
   - 將日 K 歷史收盤價序列傳入河流圖繪製真實股價紅線。
3. **財務深度鑑識純函式引擎封裝 (Forensic & Margin Engines)**：
   - 封裝 `calculateOperatingLeverage(records)` 計算營運槓桿 DOL 與營收成長加速度 $\Delta \text{YoY}$。
   - 封裝 `calculateCoreBusinessPurity(records)` 計算本業純度比率。
   - 封裝 `calculateReverseDcf(currentPrice, latestFcf, wacc, perpetualGrowth, sharesOutstanding)` 求解市場隱含 FCF 成長率。
   - 封裝 `calculateScenarioValuation(baseValuation)` 產出 Bull (+20%) / Base (歷史中位) / Bear (-20%) 區間與安全邊際。
4. **100 分制 8 維度透明評分模組 (Institutional 100-Point Scoring)**：
   - 營收成長品質 15%、獲利能力與 ROIC 15%、現金流盈餘品質 15%、財務安全 10%、競爭優勢 10%、產業前景 10%、估值吸引力 15%、催化劑與預期差 10%。
   - 每項分數均附帶客觀數據支持、扣分原因與資料信心水準。
5. **UI/UX 資訊架構重塑 (Executive Summary & Lens)**：
   - 在頂部新增常駐「01｜機構研究總覽」看板，整合核心結論、多空三理由、買進觀察區與失效停損。
   - 三表對照組件新增 `[ 8 季 | 12 季 | 20 季 ]` 分段切換按鈕。
6. **外聯 Prompt 抽屜與裁決釘選回流 (Loopback Protocol)**：
   - 建立專屬外聯 Prompt 產生器，將量化事實無損格式化為 12 分析師框架。
   - 整合現成 `strategyPinEngine`，提供抽屜式貼上解析與戰績釘選。

## Testing Decisions

- **測試原則**：遵循專案 TDD 準則，只在公開介面縫隙 (Test Seams) 編寫測試，嚴禁測試內部私有變數或脆弱實作細節。
- **測試模組與縫隙**：
  1. `lakehouseFinancialClient.test.ts`：測試雙結構 JSON 解析相容性，確保湖倉快取 100% 正確還原。
  2. `financialTurnoverEngine.test.ts` & `financialProfitabilityEngine.test.ts`：測試營運槓桿 DOL、本業純度與營收成長加速度之邊界案例（如分母為 0、虧損轉盈）。
  3. `keyMetricsEngine.test.ts`：測試 Reverse DCF 隱含成長率逆推方程與三情境安全邊際試算。
  4. `forensicAuditor.test.ts`：測試董監質押率 $\ge 50\%$ 觸發斷頭紅燈與內部人轉讓警訊。
  5. `StockAnalysisWorkspace.ui.test.tsx`：測試 8 季 / 12 季 / 20 季切換、河流圖歷史股價紅線渲染、總覽看板評分展示。

## Out of Scope

- 在本地建立針對公開資訊觀測站 (MOPS) 或 SEC EDGAR 的高頻即時網路爬蟲（避免 IP 封鎖與脆弱性維護）。
- 脫離真實數據通靈虛構法說會語氣或非公開分析師目標價共識（恪守 Zero-Mock）。
- 自動化代客下單或高頻演算法交易。
