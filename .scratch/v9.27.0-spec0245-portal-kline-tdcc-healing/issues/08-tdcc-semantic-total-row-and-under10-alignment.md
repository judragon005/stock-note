# 08 — TDCC 官方 HTML 合計列語意錨定（16/17 通吃）與散戶 10 張（1~3 級距）口徑收斂

**Parent:** #605 (Spec 0245)

**What to build:** 徹底根除 TDCC 官方歷史表單解析器因無「差異數調整」列而合計列序號為 `16`（非 `17`）導致靜默丟棄 80% 歷史週次之致命缺陷：改以分級欄位文字進行語意錨定（合計 → 總計列、差異數 → 調整列），並加入 1~15 級加總保底機制；同步將全鏈路 `under10Ratio` 統計口徑由原本誤含 10~20 張之 1~5 級距收斂為官方真實 1~10 張（級距 1~3）。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 離線解析官方 HTML 時，無論「合 計」列序號為 `16`（無差異數調整）或 `17`（有差異數調整），皆 100% 精準解析出總股東人數、400 張以上、千張大戶與散戶比例
- [ ] 若異常 HTML 表格缺漏合計列但含有效 1~15 級資料，彙總函式自動以 1~15 級（含調整列）加總推導總股數與總股東人數，不靜默歸零
- [ ] `under10Ratio` 跨全市場 OpenData CSV、官方歷史 HTML 與備援來源全面統一為級距 `1~3`（1~10 張），排除級距 `4~5`（10~20 張）
- [ ] 既有 TDCC 解析與入庫測試套件全部綠燈，並新增序號 `16` 合計列與 `1~3` vs `4~5` 級距隔離之專項回歸測試
